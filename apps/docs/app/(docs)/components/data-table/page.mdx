# DataTable

Easy to use table and datagrids built using [TanStack Table](https://tanstack.com/table/latest).

<Links component="data-table" />

## Documentation

### Install

Install the required peer dependencies to start using this component:

```sh npm2yarn
npm install @tanstack/react-table
```

<Alert intent="information" mt="16">
  `DataTable` works with both TanStack Table v8 and v9.
</Alert>

### Usage

Use the `table` prop to pass the table instance returned from the `useTable()` hook, with `columns`, `data`, and the `features` the table uses. Register each feature in `tableFeatures()`, such as `rowSelectionFeature` for `DataTableCheckbox` or `rowPaginationFeature` for `DataTableFooter`: their controls do nothing without it.

On v8, pass the table returned from `useReactTable()` with `columns`, `data`, and `getCoreRowModel`. A v8 table has every feature.

<Demo component="data-table/usage" />

### Anatomy

```tsx
import { DataTable, DataTableBody, DataTableFooter } from "@optiaxiom/react";

export default () => (
  <DataTable>
    <DataTableBody>
      <DataTableAction />
      <DataTableCheckbox />
      <DataTableLabel />
    </DataTableBody>

    <DataTableFooter />
  </DataTable>
);
```

Headers in `DataTable` are sticky by default. Set a height on the component to allow scrolling vertically when a large number of rows are present.

### Column pinning

Follow the [column pinning guide](https://tanstack.com/table/latest/docs/guide/column-pinning) and use the `columnPinning` option to pin columns to the `start` or `end` of the table (`left` or `right` in v8). On v9, register `columnPinningFeature` and `columnSizingFeature`.

<Demo component="data-table/sticky-column-usage" />

### Column resizing

Register `columnSizingFeature` and `columnResizingFeature` to let users drag the edge of a column header to resize it, and double click the edge to reset it. Set `enableResizing: false` on a column to keep its width fixed. On v8, every column is resizable by default.

By default the new width applies when the drag ends. Set `columnResizeMode: "onChange"` to resize the column while dragging.

### Row selection

Follow the [row selection guide](https://tanstack.com/table/latest/docs/guide/row-selection) to allow selecting and highlighting rows. On v9, register `rowSelectionFeature`.

Use the `DataTableCheckbox` component to automatically attach selection handlers and make the whole row selectable.

Combine `Checkbox`/`DataTableCheckbox` with `Cover` to make them easier to interact with by spanning the whole cell.

Finally, make sure to use the `DataTableLabel` in your primary cell to set the label of the row and the checkbox for screen readers.

### Row actions

Use the `DataTableAction` component to show links, buttons, or dropdown menus within rows that are only visible when the user hovers over the row.

You can enable the `primary` prop on any one of those actions to mark that as the primary action. This will automatically enable keyboard navigation within the table:

- Double click on a row to perform the primary action. When the table has no row selection (`enableRowSelection: false`, or a v9 table without `rowSelectionFeature`), or uses `selectionBehavior="toggle"`, a single click does too.
- Use up/down/left/right arrow keys to navigate between rows and actions.

Finally, make sure to use the `DataTableLabel` in your primary cell to set the label of the row for screen readers.

### Selection behavior

By default (`selectionBehavior="replace"`), a click selects only the clicked row, a double click performs the primary action, and the arrow keys move the selection.

Set `selectionBehavior="toggle"` on `DataTable` when a click should run the row's action instead, such as opening a row while other rows stay checked:

- Click a row to perform its primary action. A row without one toggles its selection.
- Use the checkbox or Space to select a row, and Shift with the up/down arrow keys to extend the selection. The arrow keys alone only move between rows.

### Highlighted row

`DataTable` keeps track of the row the keyboard is on: focusing a row, clicking it and the arrow keys move this highlight, and Tab returns to it. On TanStack Table v9, register `rowHighlightingFeature` to keep it in table state, so the app can follow it (for example to show the row in a details pane) or set it:

```tsx
import { rowHighlightingFeature } from "@optiaxiom/react";

const features = tableFeatures({ rowHighlightingFeature });

const [highlightedRowId, setHighlightedRowId] = useState<null | string>(null);
const table = useTable({
  columns,
  data,
  features,
  getRowId: (row) => row.id,
  onHighlightedRowIdChange: setHighlightedRowId,
  state: { highlightedRowId },
});
```

The value is the TanStack row `id`, so set `getRowId` to keep it stable across sorting and pagination. `table.setHighlightedRowId()` moves the tab stop without moving focus, and cells can read `row.getIsHighlighted()`.

A newly highlighted row scrolls into view when it isn't already, even when the table virtualizes it out of the DOM. Highlight a row the user can focus, one with a primary `DataTableAction` or a `DataTableCheckbox`, so Tab can reach it. To return to a list at the row the user left from, pass its id as `initialState.highlightedRowId`, and `loading` to `DataTableBody` while the rows load: the table scrolls to it once they have. A row on another page is not on the table yet, so set the page first.

### Row intent

On TanStack Table v9, register `rowIntentFeature` to color rows. `getRowIntent` reads each row, so the app keeps the state the color describes:

```tsx
import { rowIntentFeature } from "@optiaxiom/react";

const features = tableFeatures({ rowIntentFeature, rowSelectionFeature });

const table = useTable({
  columns,
  data,
  features,
  getRowIntent: (row) => (row.id === openRowId ? "primary" : undefined),
});
```

`primary` gives a row the selected rows' color without selecting it, such as the row shown in a details pane. A row with an intent keeps its color on hover.

### Pagination

`DataTable` supports both client-side and server-side pagination. Follow the [pagination guide](https://tanstack.com/table/latest/docs/guide/pagination) to learn how to implement pagination with TanStack Table.

#### Client side

Register `rowPaginationFeature` with `paginatedRowModel: createPaginatedRowModel()` and set the `pagination` state to use client-side pagination. On v8, provide `getPaginationRowModel` instead.

<Demo component="data-table/pagination-client-usage" />

#### Server side

To implement manual server-side pagination we can use `manualPagination` and `rowCount`, with `rowPaginationFeature` registered on v9. Then combine it with `onPaginationChange` and `state.pagination` to control pagination and react to changes.

<Demo component="data-table/pagination-server-usage" />

### List view

A collection page combines a search input and filter menus above the table with a primary create action. Wire search to `globalFilter` and each menu to its column's filter value, add the filtered and paginated row models (`getFilteredRowModel` and `getPaginationRowModel` on v8), and TanStack resets to the first page whenever the criteria change. Put row commands in a trailing column behind one `EllipsisMenuButton`, and use `empty` to offer a way out when nothing matches.

### Expanding rows <Badge intent="primary">ALPHA</Badge>

Follow the [expanding guide](https://tanstack.com/table/latest/docs/guide/expanding) to allow expanding and collapsing rows. On v9, register `rowExpandingFeature` with `expandedRowModel: createExpandedRowModel()`.

Use the `DataTableExpandableHeader` and `DataTableExpandableCell` components to render columns with built-in buttons for toggling rows.

Finally, combine it with the `loading` prop to show a loading state while expanded rows are being fetched. On v9, set `autoResetExpanded: false` when fetched rows go into `data`: v9 collapses every row whenever `data` changes.

<Demo component="data-table/expanding-rows-usage" />

### Virtualized

Table automatically uses virtualized rendering when rows and columns cross a certain threshold to improve rendering performance.

Columns will be virtualized when there are more than 20 columns in a table and rows will be virtualized when there are more than 20 rows rendered or if columns are also being virtualized.

## Accessibility

### Labels

- Put `DataTableLabel` in each row's primary cell. It names the row and its selection checkbox for screen readers.
- Pass `aria-labelledby` (pointing at the table's visible heading) or `aria-label` to `DataTableBody`. It names the region around the table, which takes keyboard focus when the table scrolls.

### Keyboard navigation

- Mark one `DataTableAction` per row as `primary` to enable arrow key navigation between rows and actions.
