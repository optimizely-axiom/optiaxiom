# Design Tokens

Axiom uses **CSS variables** to declare design tokens and also conveniently exports the variable names in the `theme` object.

## Declaring tokens

### CSS variables

Every token listed under [Reference](#reference) is available as a CSS variable under the `--ax-*` prefix. Spacing is not a token: see [Spacing](#spacing).

So given a tokens object like this:

```json
{
  "colors": {
    "bg.accent": "#abff44",
    "fg.success": "#03a65d"
  },
  "zIndex": {
    "popover": "3000"
  }
}
```

The following css custom properties will be available:

```css
:root {
  --ax-colors-bg-accent: #abff44;
  --ax-colors-fg-success: #03a65d;
  --ax-zIndex-popover: 3000;
}
```

And they can also be accessed via the `theme` object:

```ts
import { theme } from "@optiaxiom/react";

console.log(theme.colors["bg.accent"] === "var(--ax-colors-bg-accent)"); // true
console.log(theme.colors["fg.success"] === "var(--ax-colors-fg-success)"); // true
console.log(theme.zIndex.popover === "var(--ax-zIndex-popover)"); // true
```

### Spacing

Spacing values (`gap`, `p*`, `m*`) exist only as style props. There is no `--ax-space-*` variable and no `theme` entry for them.

Each value is a pixel count: `gap="8"` is `8px`, `p="24"` is `24px`. Use the style prop wherever you render the element. When you style markup you don't render, such as rendered markdown or a third-party widget, write the same pixel value.

### Sizing scale

Sizes, spacing, font sizes, and radii are based on `rem`, so they follow the root font size of the page, including the user's browser font size setting.

If you embed Axiom in pages you don't control (for example an overlay inside a shadow root on third-party sites), set `--ax-styles-scale` to control the size of `1rem` for Axiom. Using `max()` keeps components from shrinking on pages that reduce the root font size, while still growing when the user increases their browser font size:

```css
:host {
  --ax-styles-scale: max(1rem, 16px);
}
```

Set it on the same element the theme is declared on: `:root`, or `:host` inside a shadow root. Breakpoints always follow the browser default font size and are not affected.

## Consuming tokens

### Using style props

For all react components you can use the various style props to set the styles using tokens.

<Demo component="styles/prop-usage" />

### Consuming variables from CSS

You can also directly use the CSS variable name in your `.css` files. Nothing checks these names, and a misspelled variable silently falls back to its default, so copy names from the [Reference](#reference) below or prefer the `theme` object.

<Demo component="styles/css-usage" />

### Consuming variables from JS

Axiom exports a `theme` contract that contains a map of all tokens to the corresponding CSS custom property name.

Use this `theme` object in any CSS-in-JS solution, such as vanilla-extract `.css.ts` files, instead of writing `var(--ax-…)` by hand: TypeScript rejects a token name that doesn't exist.
